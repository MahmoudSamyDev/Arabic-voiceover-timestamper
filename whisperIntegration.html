Overview
How it fits together

The browser tab runs two threads. The main thread owns the React UI and the Web Audio API. A dedicated Web Worker owns the Whisper model and ONNX Runtime. They communicate by message passing — audio goes in as Float32Array, transcript chunks come back as JSON.

┌─────────────────────────────────────────────────────────────┐ │ Browser Tab │ │ │ │ ┌────────────────────────┐ ┌───────────────────────────┐ │ │ │ Main Thread │ │ Web Worker │ │ │ │ │ │ │ │ │ │ React UI │ │ @huggingface/transformers │ │ │ │ useTranscriptWorkflow │───▶│ ONNX Runtime Web (WASM) │ │ │ │ useAudioMetadata │◀───│ Whisper encoder+decoder │ │ │ │ │ │ │ │ │ │ ┌──────────────────┐ │ │ Runs inference without │ │ │ │ │ Web Audio API │ │ │ blocking the UI thread │ │ │ │ │ OfflineAudio │ │ │ │ │ │ │ │ Context │ │ └───────────────────────────┘ │ │ │ └──────────────────┘ │ │ │ │ └────────────────────────┘ │ │ │ │ ▼ │ │ │ ┌──────────────────┐ │ │ │ Float32Array │ Cache API │ │ │ │ (16kHz mono) ────▶│ model weights │ │ │ │ persist offline │ │ └───────────────────────────────────────────────────────────┘

The message protocol between threads is simple:

Main Thread Web Worker │ │ │──── LOAD_MODEL { modelId } ────────────▶│ │ │ downloads from HF CDN │◀─── MODEL_PROGRESS { file, % } ────────│ or reads from Cache API │◀─── MODEL_READY ───────────────────────│ │ │ │──── TRANSCRIBE { audio: Float32Array }─▶│ │ │ ONNX inference, 30s chunks │◀─── TRANSCRIPTION_DONE { chunks[] } ───│ │ │
Tech Decision
Why @huggingface/transformers, not whisper.cpp

Two paths exist for running Whisper in the browser. One aligns with your plan to download from HuggingFace.

Option A CHOSEN
@huggingface/transformers
Runs Whisper ONNX models in the browser via ONNX Runtime Web. HuggingFace hosts ready-to-use quantized models. First-party caching via Cache API — offline after one download.
+ Native HF model format, no conversion
+ Works with your planned HF download
+ Built-in chunking for long audio
Option B
whisper.cpp + WASM
Compiles whisper.cpp to WebAssembly. Potentially faster on some hardware. Requires converting PyTorch weights to ggml format and building the WASM binary.
− Custom build pipeline, not HF native
− More complex worker setup
− No built-in chunking or caching
ℹ
One important setup requirement: Multi-threaded ONNX Runtime (faster) needs SharedArrayBuffer, which needs two HTTP headers: Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp. Phase 1 adds these to Vite's dev and preview servers. They're standard for any app doing browser-side ML.
Model Selection
Choosing the right Whisper size

All sizes run fully in the browser. Larger models are more accurate but slower. For English voiceover work, whisper-base.en is the recommended starting point.

Model ID (HuggingFace) Download (q8) Speed on CPU Use case
Xenova/whisper-tiny.en ~78 MB ~realtime Fast iteration, testing
Xenova/whisper-base.en ← RECOMMENDED ~145 MB ~1.5× realtime English voiceovers, good accuracy
Xenova/whisper-small.en ~490 MB ~4× realtime High accuracy, patient wait
Xenova/whisper-tiny ~78 MB ~realtime Multilingual, fastest
Xenova/whisper-base ~145 MB ~1.5× realtime Multilingual balanced
ℹ
q8 = 8-bit quantized. Transformers.js downloads the quantized variant by default (via dtype: 'q8'), which is ~2× smaller than full precision with minimal accuracy loss. The ONNX repo contains both; only the quantized files get downloaded.

PHASE 02
Audio Preprocessing Pipeline
~45 minutes · 1 new file
Goal: Create a utility that takes the user's uploaded audio file and converts it to a Float32Array at exactly 16 kHz mono — the format Whisper expects. This uses the browser's OfflineAudioContext, which handles any sample rate, any channel count, any supported audio format.
src/utils/audioProcessing.tsTypeScript — NEW FILE
// Whisper requires 16 kHz mono Float32Array. // OfflineAudioContext handles resampling and stereo downmix natively. export async function decodeAudioToFloat32( file: File, targetSampleRate = 16_000, ): Promise<Float32Array> { const arrayBuffer = await file.arrayBuffer(); // Decode at native rate first const audioCtx = new AudioContext(); const decoded = await audioCtx.decodeAudioData(arrayBuffer); await audioCtx.close(); // Resample + downmix to 1-channel 16 kHz via OfflineAudioContext. // The spec mandates automatic stereo-to-mono downmix when channel counts differ. const offlineCtx = new OfflineAudioContext( 1, // output channels: mono Math.ceil(decoded.duration * targetSampleRate), // total output samples targetSampleRate, ); const source = offlineCtx.createBufferSource(); source.buffer = decoded; source.connect(offlineCtx.destination); source.start(0); const resampled = await offlineCtx.startRendering(); return resampled.getChannelData(0); }
ℹ
Memory note for long audio: A 30-minute file produces a Float32Array of ~29 MB at 16 kHz. This is fine. Beyond 60 minutes, consider chunking the audio before passing to the worker. For typical voiceover work this won't be an issue.
PHASE 03
Whisper Web Worker
~1.5 hours · 1 new file
Goal: Create the worker script that owns the Whisper model for its entire lifecycle. It runs ONNX inference on a background thread so the UI never freezes during transcription — even for a 20-minute voiceover.
src/workers/whisper.worker.tsTypeScript — NEW FILE
import { pipeline, env } from '@huggingface/transformers'; import type { AutomaticSpeechRecognitionPipeline } from '@huggingface/transformers'; // Cache model weights in the browser's Cache API after first download. env.useBrowserCache = true; env.allowLocalModels = false; // flip to true after running Phase 6 download env.allowRemoteModels = true; // ── Message types ─────────────────────────────────────────────────── type InMsg = | { type: 'LOAD_MODEL'; modelId: string } | { type: 'TRANSCRIBE'; audio: Float32Array }; type OutMsg = | { type: 'MODEL_PROGRESS'; file: string; progress: number } | { type: 'MODEL_READY' } | { type: 'TRANSCRIPTION_DONE'; chunks: Chunk[] } | { type: 'ERROR'; message: string }; type Chunk = { text: string; timestamp: [number, number] }; // ── State ──────────────────────────────────────────────────────────── let transcriber: AutomaticSpeechRecognitionPipeline | null = null; // ── Handler ────────────────────────────────────────────────────────── self.addEventListener('message', async (event: MessageEvent<InMsg>) => { const msg = event.data; if (msg.type === 'LOAD_MODEL') { try { transcriber = await pipeline('automatic-speech-recognition', msg.modelId, { dtype: 'q8', progress_callback: (info: Record<string, unknown>) => { if (info.status === 'progress') { self.postMessage({ type: 'MODEL_PROGRESS', file: info.file as string, progress: info.progress as number, } satisfies OutMsg); } }, }); self.postMessage({ type: 'MODEL_READY' } satisfies OutMsg); } catch (err) { self.postMessage({ type: 'ERROR', message: String(err) }); } } if (msg.type === 'TRANSCRIBE') { if (!transcriber) { self.postMessage({ type: 'ERROR', message: 'Model not loaded' }); return; } try { const result = await transcriber(msg.audio, { return_timestamps: true, chunk_length_s: 30, // process in 30-second windows stride_length_s: 5, // 5-second overlap between windows }); const output = Array.isArray(result) ? result[0] : result; const chunks: Chunk[] = (output.chunks ?? []) .filter(c => c.text.trim()) .map(c => ({ text: c.text.trim(), timestamp: c.timestamp as [number, number], })); self.postMessage({ type: 'TRANSCRIPTION_DONE', chunks } satisfies OutMsg); } catch (err) { self.postMessage({ type: 'ERROR', message: String(err) }); } } });
ℹ
chunk_length_s / stride_length_s: Whisper processes audio in 30-second windows. The stride is the overlap between consecutive windows. This is how it handles audio longer than 30 seconds without losing words at the boundaries. Transformers.js handles the chunking loop internally — you send the full audio array and get back a flat list of chunks.
PHASE 04
Whisper Service Layer
~1 hour · 1 new file
Goal: Create a service class that owns the worker, exposes a clean async API to the React layer, and handles the lifecycle (load once, reuse for all files, terminate on disposal). This is the file that replaces mockTranscript.ts as the integration point.
src/services/whisperService.tsTypeScript — NEW FILE
// Vite's way to bundle a worker as a separate module chunk. const WORKER_URL = new URL('../workers/whisper.worker.ts', import.meta.url); export type TranscriptChunk = { text: string; timestamp: [number, number]; // [startSecs, endSecs] }; type LoadOptions = { modelId: string; onProgress?: (file: string, progress: number) => void; }; class WhisperService { private worker: Worker | null = null; private loadPromise: Promise<void> | null = null; loadModel(opts: LoadOptions): Promise<void> { // Called again while loading? Return the same promise. if (this.loadPromise) return this.loadPromise; this.worker = new Worker(WORKER_URL, { type: 'module' }); this.loadPromise = new Promise((resolve, reject) => { const w = this.worker!; w.addEventListener('message', ({ data }) => { if (data.type === 'MODEL_PROGRESS') opts.onProgress?.(data.file, data.progress); if (data.type === 'MODEL_READY') resolve(); if (data.type === 'ERROR') reject(new Error(data.message)); }); w.postMessage({ type: 'LOAD_MODEL', modelId: opts.modelId }); }); return this.loadPromise; } transcribe(audio: Float32Array): Promise<TranscriptChunk[]> { return new Promise((resolve, reject) => { if (!this.worker) { reject(new Error('Model not loaded')); return; } const w = this.worker; const handler = ({ data }: MessageEvent) => { if (data.type === 'TRANSCRIPTION_DONE') { w.removeEventListener('message', handler); resolve(data.chunks); } if (data.type === 'ERROR') { w.removeEventListener('message', handler); reject(new Error(data.message)); } }; w.addEventListener('message', handler); // Transfer the ArrayBuffer — zero-copy. The main thread gives up ownership. w.postMessage({ type: 'TRANSCRIBE', audio }, [audio.buffer]); }); } dispose() { this.worker?.terminate(); this.worker = null; this.loadPromise = null; } } // Singleton — one worker, shared across all uploads in a session. export const whisperService = new WhisperService();
⚠
Transferable objects: Notice postMessage({ audio }, [audio.buffer]) — the second argument transfers ownership of the underlying ArrayBuffer. After this call, audio in the main thread is detached (zero length). This is intentional: it avoids copying potentially 30 MB of audio data. Don't access audio after sending it to the worker.

Going Offline
Downloading Whisper from HuggingFace

By default the app downloads the model from HuggingFace's CDN on first use and caches it in the browser. If you want true offline-first operation (model lives in the project, no initial download ever), follow these steps.

1
Install the HuggingFace CLI
One-time setup. Requires Python 3.8+.
Terminal
pip install huggingface_hub
2
Download the model into the project's public folder
The path structure must match exactly how transformers.js resolves it: public/models/{namespace}/{model-name}/
Terminal — run from the project root
# Create the directory (namespace matters)
mkdir -p ./public/models/Xenova
# Download only the ONNX files + config JSONs (skip PyTorch .bin)
huggingface-cli download Xenova/whisper-base.en \ --local-dir ./public/models/Xenova/whisper-base.en \ --include "*.json" "onnx/*.onnx"
# Prevent models from being committed to git
echo "public/models/" >> .gitignore
3
Switch the worker to local mode
In whisper.worker.ts, flip the two env flags:
src/workers/whisper.worker.ts — two lines to changeTypeScript
env.allowLocalModels = true; // ← was false env.allowRemoteModels = false; // ← was true (prevents fallback to CDN) env.localModelPath = '/models/'; // ← add this line // The model ID 'Xenova/whisper-base.en' now resolves to: // /models/Xenova/whisper-base.en/ (served from public/ by Vite)
ℹ
What gets downloaded: The --include "onnx/*.onnx" flag fetches both the full-precision and quantized encoder/decoder files. With dtype: 'q8', transformers.js uses only the *_quantized.onnx variants. Total on disk: ~145 MB for base.en.
⚠
Alternative — git LFS clone: If you prefer git: git lfs install && git clone https://huggingface.co/Xenova/whisper-base.en ./public/models/Xenova/whisper-base.en. Requires git-lfs installed. The CLI method above is more reliable for first-timers since it skips LFS setup.

Verification
Testing checklist

Work through these in order after completing all six phases. Each one catches a different failure mode.

Vite starts without errors. Run npm run dev. Check the browser console for COOP/COEP header errors — DevTools Network tab → click any request → Response Headers should show both headers.
Model downloads on first upload. Upload any MP3. The UI should enter model-loading state and show download progress. DevTools Network → filter "onnx" to see the files arriving.
Model loads from cache on second upload. Upload again (same or different file). The model-loading state should skip or be very fast (< 1 second). DevTools Network → filter "onnx" → should show "(from cache)" or "(from disk cache)".
Audio decodes correctly. In DevTools console, temporarily log the Float32Array from decodeAudioToFloat32: confirm length ≈ (file_duration_in_seconds × 16000), values in range −1.0 to 1.0.
Transcript chunks have valid timestamps. After transcription, open the completed state and confirm each TranscriptLine.timestamp is in MM:SS format and monotonically increasing.
UI stays responsive during transcription. While a file is processing, try scrolling the page and clicking other elements. The UI should never freeze — if it does, the audio decoding or model load is happening on the main thread (not the worker).
Build succeeds. Run npm run build and confirm no TypeScript errors. Preview the production build with npm run preview and verify the worker URL resolves correctly (no 404 on the worker chunk).
(Offline mode only) Local model loads without network. Put the browser in offline mode (DevTools → Network → Offline). Upload a file. The model should load from /models/ with no network requests.
